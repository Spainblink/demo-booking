# Бронирование переговорных

API для бронирования переговорных комнат в офисах Москва и Новосибирск.

Стек: PHP 8.4, Laravel 13, PostgreSQL, Docker.

## Запуск

```sh
docker compose up -d --wait
docker compose exec app php artisan migrate:fresh --seed
```

API: `http://localhost:8000/api`

## Тесты

```sh
docker compose exec app php artisan test
```

Тесты используют отдельную БД PostgreSQL `testing`.

## Авторизация

Все методы требуют заголовки:

- `Authorization: Bearer <токен>`
- `Accept: application/json`

Без `Accept` запрос без токена может вернуть 500 вместо 401.

| Пользователь | id | Токен |
| --- | --- | --- |
| Анна | 1 | `anna-token` |
| Борис | 2 | `boris-token` |

Токены постоянные только для демонстрации (Sanctum).

## Данные сидера

| Офис | Часовой пояс | Комнаты (id) |
| --- | --- | --- |
| Москва | Europe/Moscow | Арбат (1), Тверская (2), Остоженка (3) |
| Новосибирск | Asia/Novosibirsk | Обь (4), Академгородок (5) |

Рабочее время офисов: **09:00–20:00** по локальному времени офиса комнаты.

## API

| Метод | Адрес | Описание |
| --- | --- | --- |
| GET | `/api/bookings` | Список броней текущего пользователя (пагинация) |
| POST | `/api/bookings` | Создать бронь |
| DELETE | `/api/bookings/{booking}` | Отменить бронь (только автор) |
| GET | `/api/rooms/{room}/bookings/today` | Брони комнаты на «сегодня» |

### POST `/api/bookings`

Автор всегда берётся из Bearer-токена. Поле `user_id` в теле, если передано, игнорируется.

**Тело:**

| Поле | Тип | Правила |
| --- | --- | --- |
| `room_id` | int | обязателен, существующая комната |
| `title` | string | обязателен, до 255 символов |
| `starts_at` | string | обязателен, ISO 8601 (любое смещение) |
| `ends_at` | string | обязателен, ISO 8601, позже `starts_at` |

**Бизнес-правила:**

- длительность от 15 минут до 4 часов;
- границы на сетке 15 минут (`10:00`, `10:15`, …);
- бронь целиком в 09:00–20:00 по TZ офиса комнаты;
- брони одной комнаты не пересекаются; стык (`10:00–11:00` и `11:00–12:00`) разрешён.

**Ответы:**

- `201` — бронь создана;
- `401` — нет/неверный токен;
- `422` — ошибки валидации / бизнес-правил (`errors` по полям).

Пример:

```sh
curl -X POST http://localhost:8000/api/bookings \
  -H "Authorization: Bearer anna-token" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"room_id": 1, "title": "Планёрка", "starts_at": "2026-11-09T10:00:00+03:00", "ends_at": "2026-11-09T11:00:00+03:00"}'
```

### DELETE `/api/bookings/{booking}`

- `204` — отменена;
- `403` — отменяет не автор;
- `404` — бронь не найдена;
- `401` — нет/неверный токен.

### GET `/api/bookings`

Возвращает только брони текущего пользователя, по 20 на страницу.

### GET `/api/rooms/{room}/bookings/today`

Список броней комнаты на текущую дату в TZ приложения (UTC). Формат элемента: `time`, `author`.

## Гонки при параллельном создании

Для последовательных запросов пересечения блокируются проверкой интервалов.

При параллельных `POST` на одну комнату используется транзакция и блокировка строки комнаты `SELECT … FOR UPDATE NOWAIT`:

- если комната уже залочена другим запросом — сразу `422` с понятным сообщением (без ожидания);
- после получения блокировки снова проверяется пересечение интервалов.

Альтернатива на уровне БД: exclusion constraint PostgreSQL на `tstzrange(starts_at, ends_at)` по `room_id`. Или `FOR UPDATE` без `NOWAIT` с ожиданием коммита или роллбэка другой транзакции.
